Cycle 1 established the working method for this Pipes campaign: test one allocator hypothesis per cycle against the incumbent manifest on the frozen 15-case open set, report per-case KPI deltas rather than aggregate-only claims, and keep the incumbent configuration when no variant wins. Source inspection of the seeded allocator showed it already indexes free spans by (size, start) with a slack-weighted fit score, a flat near-fit miss penalty (scale 60, window-based), parity cohort slabs, geometric-lane alignment, a LIFO lane, and a tightly budgeted Monte Carlo lookahead (small decision and gap-count gates that disable it in large states), so promising leads are the tunable scoring weights and lookahead budgets, not new data structures. Promising: magnitude-weighted miss penalties — charging each missed request length in the fit score in proportion to its magnitude via a small exponent-variant table instead of the flat scale (the cycle-3 hypothesis, deferred twice before being selected); sweeping the flat penalty-scale indices; extending lookahead coverage only if CPU stays far below the limit. Unpromising: big-gap fallback before expansion — the incumbent already evaluates the smallest fitting gap even when its slack exceeds the scan window, so that hypothesized dead path does not exist. Acceptance caveat: the cycle-1 submission (behaviorally incumbent flat scale) and the cycle-2 submission (raised rollout budget) both returned a zero combined_score with correct=false and no usable per-case deltas, so neither configuration is refuted nor validated, and the recurring zero-score pattern on near-incumbent builds is suspected execution-side rather than allocator-side harm; keep both variant indices re-selectable. Treat open-set gains as overfittable signals, never closed-set predictions.
