Что изменено в ядре

Прежний код оценивал будущую полезность свободных участков только при более 4096 активных трубах. В меньших состояниях оставался грубый штраф за неиспользуемый остаток. Теперь существующая DP-оценка доступна уже при 128 live, 256 наблюдавшихся событиях и 32 удалениях в окне. Она сравнивает, сколько полезной вместимости теряется после укладки текущей трубы.

Спрос и частота удалений для этой модели считаются по последним 256 событиям вместо 2048, чтобы старый режим быстрее переставал влиять на выбор. Остальные side/cohort/LIFO истории сохранены. Все признаки причинные; в выбранном исходнике нет таблиц публичных ответов.

Проверены три отдельных гипотезы и одна композиция. Ослабление parity-confidence отклонено: наDEV дало крупную потерю−0.108949. Короткое окно без расширения области DP почти ничего не меняло. Измеренная ранняя версия gate исправлена с array capacity на реальное число событий до независимой calibration; исходная ревизия сохранена.

Что ломалось в гибриде

На прежних шести проигрышах разделены физическая геометрия и внутреннее состояние. В old-final105/120 геометрия совпадала, но import обнулял уже потраченный MC budget. Лишний rollout менял размещение, затем требовал дополнительного рытья. Точный перенос shadow при совпадении live PID-позиций иT исправляет эти два случая.

В old-final054/081/118/126 размещения отличались до переключения. Для118 накопилось 520 лишних метров: 452 промежутка длины 5 вместо 146. Перенос metadata это не исправляет. Handoff repair тоже не гарантирует рост KPI: на old-final090 он потерял 60 м, потому что прежний сброс бюджета случайно помогал.

Диагностика шести проигрышей · Проверка точного handoff

В новой calibration чистый online оказался предпочтительнее гибрида по заранее заданному критерию. Final даёт их почти равенство; выбор после final не пересматривался.

Общий счёт, а не только Open15

Известные веса: 32.1 открытых + 84 закрытых. Используем чувствительность Open15 +84×((1−p)×ordinary_macro +p×prefix_macro), где доля ловушекp неизвестна. Это не прогноз официального счёта.

На final новая политика даёт от+0.535 до+0.648 условного балла к прежнему гибриду приp от 0 до 1. К прежнему online: от+0.547 до+0.747. Потерю 0.08345 Open15 к hybrid окупает средний взвешенный прирост закрытого KPI около 0.000993.

Относительно исторического максимума Open15=30.75747405 потеря 0.73821; порог окупаемости около 0.008788 закрытого KPI. Полный replay в этом раунде повторно не сравнивался. Нельзя из этой таблицы заключить превосходство над любой стратегией на любом закрытом распределении.

Ресурсы и границы проверки

Выполнено 652 официальных интерактивных прогонов, из них 212 для выпуска. Финальные trench совпадают с независимой полной проверкой занятости. Пять нагрузочных входов имеют по 200000 команд: три заранее сгенерированных и два дополнительных после freeze для умеренной популяции и пересечения 4096 live. Последние два не использованы как свидетельство качества или для настройки.

Сборка C++17, один solver worker; CPU считается user+system процесса. Windows 10/G5420 и MSVC нативно не проверены. Пакет содержит runner с закреплением на одном CPU. Локальные замеры нельзя пересчитать по частоте процессора.

Оставшиеся ограничения: MC rollout продолжает моделировать прежний gap policy; DP и прогноз иногда расходятся. Lifetime confidence может кратко сохраняться ниже 4097 live до обновления модели. DP ограничен 512 состояниями, но обновляется и по смене спроса — строгой гарантии 5 с на целевой машине нет. Независимая проверка исходника.
