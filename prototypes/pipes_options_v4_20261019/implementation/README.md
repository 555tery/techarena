# Pipes options v4: fixed recipe, frozen before collection

Only allocator primitives and causal feature code are copied from v3; no old labels or model are used. This is an isolated prototype, with no platform access.

Four options: 0 best-fit left, 1 best-fit right, 2 lowest-address fitting span left, 3 anchored macro (first placement BF left, the remaining three BF right). With no fit, use minimal tail extension and the corresponding endpoint. First-fit scans at most 40 size buckets; bucket40 includes all spans>=40. Pipes cannot move. No pool or free memory is introduced. This action-space choice was fixed before fitting: the anchored macro can solve `[7,7,6,-2,5,-1,-3,15]` in20m; four pure endpoint rules cannot express that sequence. Under hold1, option3 degenerates to BFleft.

Options persist for four positive commands. Deletions preserve remaining commitment. Before any placement, eligibility is live<=12 and trench<=160; failure cancels the option and places BF. A new eligible placement after cancellation starts a new boundary. Deletion observation uses the same cancellation guard. Runtime consumes one command then flushes its response. The causal feature vector is State.features(current_length, BF_action), 128 float32 values. Current length and full observable prefix are in the observable key; future commands, horizon and input weight never enter features or policy.

Teacher input: official `weight N`, N nonzero commands, final0, EOF; N<=128. `teacher --input FILE --output LABELS.jsonl --stats STATS.json`. MODEL_HEADER compile-time selects current model (default untrained BF). Actual roll-in is always that model with hold4, no teacher mixing. First eight natural eligible option boundaries are labeled, including ties. No future-dependent sampling filter.

For each root option, execute the whole option block, then beam-search the complete remaining suffix, width8, branching four options at each eligible block boundary. Cancellation follows runtime; an ineligible stretch is deterministic BF until a new eligible boundary. Each root preserves its complete BF suffix outside the beam, so no width-pruned answer can exceed that upper bound. Objective is final trench. Beam pruning uses current trench and the reference bound; ties use fragmentation then physical key. Witnesses include every future placement, effective option (-1 for fallback), block_id and coordinates. STATS records actual roll-in placements, allowing independent own-state reconstruction.

Exactly three teacher/fit waves, orchestrated externally: untrainedBF on fresh32 inputs -> M1; M1 own-rollin on fresh32 -> M2 fit on aggregated64; M2 own-rollin on fresh32 -> M3 fit on aggregated96. Final model is always M3, no checkpoint selection. M1 is retained only as learning history. The primary no-own-state-training control uses BF-only roll-in labels on the SAME96 inputs and the identical tree recipe; it is collected and trained separately by the root. Fresh evaluation is external, and separate from training.

`python train.py --labels-dir LABEL_DIRECTORY --out MODEL_DIRECTORY` reads all jsonl recursively. All states, ties included. Targets gain_i=(cost0-costi)/20. Fixed multioutput sklearn DecisionTreeRegressor(max_depth=5,min_samples_leaf=8,random_state=20261019). Each complete observable_key group has equal total sample weight, preventing repeated forks dominating. BF is selected unless maximum predicted gain>=0.25 (5m heuristic, no confidence claim); ties choose the lowest option index. There is no hyperparameter selection, scaler, validation metric or checkpoint selection. Features are coerced to float32 before training/inference; exported split thresholds and leaf values preserve double precision.

Export includes model.hpp, fit.json, sklearn tree JSON, parity fixtures, and SHA256 manifest. `python parity.py --model-dir MODEL_DIRECTORY` compares fixtures against compiled C++ prediction and option selection. This is inference verification, not policy performance evidence.

`make MODEL_HEADER=/absolute/path/model.hpp` builds teacher and solver; use `make -B` when changing the model path to force recompilation. `solver-hold1` uses the same weights with OPTION_HOLD=1; `solver-bf` sets OPTIONS_ENABLED=0. Default `model.hpp` is explicitly untrained. stderr/STATS counters expose decisions, non_bf_options, continuation_placements, changes, cancellations and active_crossed_deletions. Input for solver is only the command stream (no weight/N).

Implementation smoke tests use tiny handmade fixtures only. No actual teacher wave, real dataset fit, holdout, Open15, old validation or platform action is authorized for this implementation task. Teacher search is a bounded heuristic upper bound, not a global optimality certificate.
