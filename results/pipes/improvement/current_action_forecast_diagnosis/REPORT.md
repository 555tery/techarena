# Open15: ретроспективная диагностика первого MC-действия

## Область проверки

Отчёт охватывает только первый фактический вызов MC в каждом из 9 подходящих кейсов Open15. Для заранее зафиксированных действий запускался точный оставшийся суффикс с замороженным продолжением allocator. Это ретроспективные результаты контрфактических продолжений, а не оценка онлайн-выигрыша и не подтверждение качества на скрытых тестах. Правило по этим результатам не выбиралось и не настраивалось.

Во всех 9 кейсах выбранное MC действие сравнялось с лучшим точным суффиксным исходом среди shortlist: regret равен нулю. Единственный положительный sampled omitted-action gain — кейс 5: старт трубы 136 дал 62 600 м траншеи, на 160 м меньше лучшего shortlist исхода (62 760 м). В остальных кейсах sampled gain равен нулю. Для кейса 9 протестировано 8 из 81 физически допустимого действия вне shortlist, поэтому нулевой gain не исключает непроверенные варианты. Действия используют общие состояния и суффиксы; различия нельзя суммировать как достижимую экономию.

Полная таблица из 121 физического действия находится в [`per_action.csv`](./per_action.csv). Для каждого действия там указаны членство в shortlist/expanded set, ранги, замороженные MC score и оценка траншеи по 12 rollout для shortlist, forced outcome если действие было в preregistered выборке, длина суффикса, статус, CPU/RSS, score и хеши stdout/stderr. Непроверенные действия явно помечены.

## Gate и ресурсы

- Валидны все 48 из 48 preregistered forced replay: 22 shortlist действия и 26 sampled действий вне shortlist; среди них 9 selected-action controls. Записей `MC_FORCE_INVALID` нет.
- Frozen reference и instrumented no-force raw stdout совпали побайтно на всех 15 кейсах. Во всех forced replay stdout до целевой команды совпал с обоими baseline. Все 9 выбранных controls совпали с baseline целиком. Ответ на целевую команду совпал с запрошенной координатой; длина каждого суффикса соответствовала протоколу.
- Фактическая работа по суффиксам: 947,532 применений команд (заранее зафиксированный верхний предел — 3,081,716). Сумма CPU solver-процессов — 5.285419 с; максимум на один replay — 0.959828 с. Максимальная RSS — 7.187500 МиБ. Сумма записанного wall orchestration — 37.258 с; максимум — 7.500 с. Все отдельные CPU/RSS значения ниже лимитов 5 с и 256 МиБ.
- Использован локальный macOS harness и замороженный interactor; сайт и Docker не использовались.

## Ошибки запуска и исправления

- Первый validator ошибочно искал каталог `runs/1`; официальный harness при единственном входе `5.in` пишет в `runs/5`. Поэтому первоначальная запись в `progress.jsonl` пометила run_order 0 invalid. Файл сохранён побайтно без изменений и по-прежнему содержит ложную запись. Отдельный [`manual_validation_audit.json`](./forced_replays/manual_validation_audit.json) повторно проверил сохранённый вывод из `runs/5`; все условия прошли, audit supersedes исходную запись. Run_order 0 не повторялся.
- Первый continuation runner выполнил run_order 1 и сохранил harness outputs, затем завершился с `TypeError` при записи текстовой JSON-строки в файл прогресса, открытый в бинарном режиме. Сохранённый запуск проверен по файлам и занесён в `continuation_progress.jsonl`; повторного solver/harness запуска для него не было. Следующий runner прошёл run_order 2–47 последовательно.
- Независимая проверка всех 48 каталогов запусков подтвердила hashes входов/ответов, target state, env/force, отсутствие invalid, response, prefixes, suffix counts и controls. Source, binary, preregistration, action manifest, frozen final и исходный progress не менялись.

## Ограничения вывода

Проверялись только preregistered действия в одном состоянии на кейс. В частности, вне shortlist тестировалась фиксированная подвыборка, а не все физически допустимые действия. Суффикс использовался только для ретроспективной оценки; данные не показывают, что онлайн-классификатор или новая политика улучшат score.
