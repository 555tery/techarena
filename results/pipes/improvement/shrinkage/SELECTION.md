# Предварительно заданный критерий отбора

До новых прогонов зафиксирован единый критерий для кандидатов, `recent_unfit_s50` и policy4.

1. Каждый допустимый вариант проходит официальный интерактор на всех 15 открытых тестах и четырёх существующих development synthetic-потоках. Невалидный результат исключается.
2. Для кандидата считаются относительные оценки к policy4 на двух наборах:
   - `R_open = open_weighted_score / 28.375837599373007`;
   - `R_dev = dev_weighted_score / 1.870543569789272`.
3. Основной критерий — `R_robust = min(R_open, R_dev)`. Он выбирает максимальную худшую относительную оценку по двум наборам, не позволяя большому выигрышу на открытых тестах скрыть синтетическую просадку. При равенстве до `1e-9` выбирается большая геометрическая средняя `sqrt(R_open * R_dev)`, затем больший open score.
4. Policy4 и `recent_unfit_s50` включены как контрольные варианты. Если лучший адаптивный вариант имеет `R_robust <= 1`, фиксируется, что адаптивного улучшения на этих двух наборах не найдено; policy4 остаётся опорной стратегией. Итог не трактуется как оценка скрытых тестов.

Development-набор состоит из неизменяемых файлов `data/pipes/synthetic/development/*.in` с суммой весов 4.0. Данные и результаты любых frozen synthetic suites исключены из настройки и выбора. Параметры кандидатов и их исходники будут перечислены в manifest до сравнения; после фиксации победителя параметры не меняются.
