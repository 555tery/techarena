# Локальная проверка coalescence-policy

Здесь подготовлен независимый набор синтетических Pipes-потоков для проверки
общей идеи: можно ли будущими онлайн-размещениями уменьшить число мелких
свободных интервалов, оставшихся после удалений, и чаще освободить соседние
участки вместе. Набор не содержит результатов solver и не предназначен для
добавления к официальному score.

## Зафиксированный дизайн

Для разработки предусмотрены 12 потоков по 15–25 тыс. команд. Их `.in` файлы
уже созданы в `inputs/development/`. Для финальной проверки зафиксированы ещё
12 потоков: десять по 30 тыс. команд и два по 200 тыс. (near-LIFO и batched
cohort). Seeds и профили закреплены в `manifest.json`; диапазоны не пересекаются:
development использует `71527001–71527012`, sealed_validation —
`71527101–71527112`.

В каждом наборе представлены все восемь семейств (по одному или два случая):

| Профиль | Что меняется в потоке |
|---|---|
| `mixed_iid_uniform` | Равномерные длины 1–40 м, случайные вставки и удаления |
| `near_lifo_local` | Удаление в основном среди недавних PID, с редким случайным контролем |
| `fifo_control` | Удаление самого старого живого PID |
| `random_deletion_control` | Случайный живой PID и немного повышенная частота удалений |
| `increasing_size_regime_blocks` | Растущие диапазоны длин по блокам |
| `decreasing_size_regime_blocks` | Те же диапазоны в обратном порядке |
| `random_size_regime_blocks` | Диапазон длины случайно меняется между блоками |
| `batched_cohorts_noisy_survivors` | Удаление большей части когорты пакетами, с живыми остатками и шумовыми вставками |

Когорты и близкие по времени удаления напрямую создают возможности для
объединения свободных соседних участков. IID, FIFO, случайные удаления и
переменные блоки нужны как контроль: преимущество должно переноситься на разные
порядки жизни труб, а не только на один шаблон удалений. Дизайн задан независимо
от solver. Входы построены только из новых seed; из официального input15 не
читались значения, PID или префиксы, и генератор их не использует.

## Генерация и граница sealed

Генератор использует только Python standard library и фиксированные
`random.Random` seeds. После генерации он проверяет объявленное число команд,
длины труб, каждое удаление против множества живых PID, конечную загрузку и
ограничение объёма; затем повторно разбирает файл через
`tools.pipes_harness.parse_test`. Последний `0` — терминатор вне объявленного
числа команд.

Development создан сейчас:

```sh
python3 results/pipes/improvement/case15_coalescence_local_20261017/validation/generate.py --suite development
```

В профилях без когорт генератор удерживает число живых труб примерно между
180 и 1800, чтобы сравнивать политики удалений при устойчивой нагрузке. При
обычной нагрузке решения о вставке и удалении принимаются с вероятностью 1/2;
`random_deletion_control` использует вероятность удаления 0.56. `near_lifo_local`
с вероятностью 0.88 выбирает одну из 12 самых новых живых труб среди последних
64 PID. Когортные параметры и все пороги также записаны в manifest.

Sealed seeds и профили закреплены сейчас, но сами sealed-файлы создаются только
после выбора и фиксации не более двух кандидатов на development. После freeze
передайте генератору идентификатор набора замороженных кандидатов:

```sh
python3 results/pipes/improvement/case15_coalescence_local_20261017/validation/generate.py --suite sealed_validation --freeze-id '<candidate-hashes-or-freeze-label>'
```

Генератор откажется создавать sealed без `--freeze-id`, затем запишет SHA-256 и
валидационную сводку каждого входа в `manifest.json`. После этого допустимо одно
финальное сравнение кандидатов на `inputs/sealed_validation/`. Не меняйте seeds,
профили или генератор после просмотра sealed-метрик.

Ни solver, ни платформа при подготовке набора не запускались. Здесь нет KPI,
score или выбора стратегии.
