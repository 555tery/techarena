# Case 15: точный offline-oracle на трёх коротких суффиксах

## Результат

На первом выбранном кластере расширений oracle не нашёл выигрыша. На двух следующих он нашёл hindsight-экономию **20 м** и **40 м**. Эти расхождения указывают на два разных геометрических механизма: внутренний сдвиг трубы, чтобы после фиксированных удалений собрать следующий интервал длиной 33 м; и сдвиг на 1 м к правому краю, чтобы удаление соседней трубы объединило 34 м с оставленным 1 м и позволило поставить трубу длиной 35 м без копки.

Это точные результаты только для конечных суффиксов с заранее зафиксированными начальными состояниями. Oracle знает команды внутри каждого суффикса. Результаты не являются причинным алгоритмом и не предсказывают экономию на продолжении потока.

## Проверка трассы и границы исследования

Вход case 15 содержит 200 000 команд. Текущий champion source `champion_cohort_slabs.cpp` имеет SHA-256 `43bfbdadbae18ac180d1e59b6631342cfe1bef99190a449838f0470d6f220200`; его локальный case-15 transcript совпадает с сохранённым frozen transcript, SHA-256 `0382b67c434136d5a015c37ccd4749d35624418ec61eece53af28fe74221bd0e`. SHA-256 входа — `0b37a067bbe01429414ba20096e0a30fc9c424f7f364d101f71c32b85fe3a353`.

Повторный просмотр трассы подтверждает в командах 100001–110000 **493 расширения на 17 220 м**. До **491** из этих расширений суммарного свободного объёма хватало для трубы; в двух случаях объёма было недостаточно. Все три DP-окна выбраны по порядку ранних кластеров, до просмотра oracle-результатов. Их начала — точные состояния baseline после указанной команды; суффикс состоит только из следующих команд исходного case 15.

DP перебирает **каждую целочисленную координату начала**, которая помещается в свободный интервал; учитывает фиксированные удаления, новые трубы и расширения траншеи секциями по 20 м. Расширение для конкретного старта минимально достаточное. Лишнюю пустую копку можно отложить до первой команды, использующей её, поэтому она не может улучшить длину траншеи в конце суффикса. Поиск ограничен baseline-длиной траншеи в конце окна: траектория длиннее неё не может дать выигрыш. Все три окна завершили полный перебор, лимиты состояний не сработали. Сохранённые baseline-ответы повторно проверены на геометрическую допустимость из каждого зафиксированного состояния.

## Что означает найденный запас

- Окно A показывает, что ранняя серия расширений в этом пяти-командном фрагменте уже достигает минимума по итоговой длине. Здесь менять tie-break или край укладки ради локального suffix-KPI нечего.
- В окне B oracle предвидит три конкретных удаления и сохраняет место перед первой трубой. Все 32 оптимальных первых действия сдвинуты вправо относительно baseline; большинство — внутренние позиции, а минимально-копающий оптимальный набор — 2 секции, старт 241478–241487 (9 внутренних позиций и один правый край). Это hindsight-зависимость от того, какие именно интервалы откроют удаления.
- В окне C полезно не «сохранять хвост» в целом, а оставить ровно 1 м со стороны соседа, которого вскоре удалят. Доступная oracle информация включает удаление PID 80252 на следующей команде; online-размещение в команде 100146 этого знать не может.

Из результата C можно вывести узкую причинную гипотезу для отдельной будущей проверки: если **по уже наблюдавшимся** удалениям у соседней трубы повышен риск скорого освобождения, выбирать край так, чтобы slack оставался со стороны соседа и мог объединиться с его интервалом. В этом фрагменте доказан только hindsight-механизм; пригодность доступной до размещения оценки риска не проверялась. Подгонять правило под PID, номер теста, координату или данную последовательность нельзя.

## Точность и ограничения

Oracle точен для указанной модели и конечного objective: минимизировать trench length ровно на последней команде окна. В каждом переходе рассматриваются все допустимые целые старты до baseline-финала; для каждого старта берётся минимальное число секций, достаточное для конца трубы. Ни beam width, ни sampled candidate gaps не использовались.

Окна не замкнуты по дальнейшей судьбе оставшихся труб: последующие команды после конца фрагмента сознательно не оцениваются. Поэтому 20 м и 40 м — точные локальные hindsight-свидетельства, а не гарантированная экономия полного case 15. Три выбранных окна не представляют все 493 расширения. Кандидат solver не создавался; Open15/holdout, website, Docker и дополнительные тестовые потоки не запускались. `src/pipes.cpp` и frozen/canonical файлы не изменялись. В рабочей папке нет `.git`, поэтому артефакты изолированы отдельным каталогом, без отдельной Git-ветки.
