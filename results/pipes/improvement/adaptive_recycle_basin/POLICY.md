# Предзаданный дизайн: adaptive recycle basin

## Мотивация

Замороженный final уже использует best-fit по недавним размерам, bounded MC, серию одинаковых размещений и специальный edge/lifetime контекст. Ранее проверенные глобальные стороны, половины траншеи, фиксированный хвост, near-LIFO tail lane, lifetime ties и size-cohort/segregated зоны не стали более сильной общей политикой. Поэтому этот кандидат использует другой сигнал: **географию фактически освобождённых интервалов**, накопленную только из уже обработанных удалений.

Гипотеза: если недавние освобождения пространственно сосредоточены, близкие к этой динамической области fitting gaps могут быть полезной локальной «recycle basin». Слегка менее точный gap внутри неё иногда может быть выгоднее, чем расходовать хороший свободный интервал за пределами области. При широко распределённых удалениях правило должно само ослабляться.

## Онлайн-правило

Хранятся последние до 64 удалённых интервалов. После каждого удаления обновляются пространственные границы:

- центры недавних удалённых интервалов кодируются в половинных метрах;
- нижняя граница — эмпирический 10-й перцентиль центров минус медианная длина недавних удалённых труб;
- верхняя граница — 90-й перцентиль плюс та же медиана;
- границы ограничиваются текущей длиной траншеи.

Для текущей трубы длины `L` измеряется доля траншеи за пределами этой области и полнота окна `n/64`. Максимально допустимая цена резервирования равна

```text
credit_m = floor(L * max(0, 1 - region_width / trench_length) * n / 64)
```

Среди fitting gaps внутри области выбирается лучший с существующей fit-cost. После обычного выбора gap текущим final, включая его MC-решение, gap внутри recycle basin заменяет выбранный только когда его cost не превышает cost выбранного gap более чем на `credit_m * history_size`. Тем самым область динамически сдвигается и меняет ширину по пространству последних удалений, а допустимое ухудшение выбора уменьшается, когда поток теряет пространственную концентрацию.

Правило не читает будущие команды, тест ID, score или абсолютный номер операции; не делит трубы на группы по размеру и не копирует parity/size-cohort. Величина текущей трубы входит непрерывно только в допуск по потере fit-cost. Те же границы и переход состояния добавлены в ограниченный rollout simulator.

## Заранее заданный gate

Сначала — только official cases 5, 9, 15 с официальным harness, относительно свежесобранного frozen final baseline. Полный Open15 и holdout-v2 запускать только если сумма weighted score 5/9/15 у candidate строго выше baseline. При положительном gate требуются полный Open15, holdout-v2, четыре старых development synthetic плюс минимум 10 новых независимых синтетических потоков, затем строгая сборка и ресурсная сводка. При невыигрышном gate сохранить отрицательный результат и не запускать полный harness.
