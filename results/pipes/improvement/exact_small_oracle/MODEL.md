# Exact offline oracle: модель и границы

## Назначение

Эта ветка строит точный hindsight-оракул для маленьких фиксированных потоков
TECH ARENA Pipes. Он минимизирует окончательную длину траншеи и служит только
диагностикой regret frozen final. Будущие команды доступны оракулу по
определению offline-задачи; этот поиск не является online-политикой.

Frozen final и `src/pipes.cpp` читаются только по hash. Сайт и Docker не
используются.

## Точная модель переходов

Команда потока — положительная длина `L` или отрицательный PID `-p`; финальный
терминатор `0` не входит в список команд. Состояние после команды:

- `T`: уже выкопанная длина, кратная 20 м;
- `A`: отображение активных PID в полуоткрытые интервалы `[x, x+L)`.

Начальное состояние: `T=0`, `A=∅`; PID положительных команд нумеруются с 1.

Для команды размещения длины `L` оракул выбирает целое `x ≥ 0`, такой что новый
интервал не пересекается ни с одним интервалом из `A`. Минимальное число новых
секций и следующий размер траншеи:

```text
T' = 20 * ceil(max(T, x + L) / 20)
digs = (T' - T) / 20
```

Затем новый PID добавляется в `A`. Это точно реализует возможность выкопать
минимальное число секций, необходимое для конца трубы. Любое большее число
секций доминируется: оно только увеличивает необратимый `T`; тот же пустой
суффикс можно выкопать при первой будущей укладке, которой он понадобится.
Дополнительная копка не создаёт нового пространства вне этого суффикса и не
меняет занятость уже размещённых труб.

Для удаления `-p` интервал PID `p` удаляется из `A`, а `T` не меняется. Другие
трубы не двигаются. Условие задачи гарантирует удаление активного PID.

Целевая функция — минимальный `T` после всех команд. Числитель KPI одинаков для
всех размещений данного входа и на выбор оракула не влияет.

## Ограниченный класс и полнота

Первая версия поддерживает фиксированные валидные потоки со следующими
ограничениями:

- от 1 до 3 положительных команд;
- каждая длина — целое число от 1 до 40 м;
- сумма длин всех размещённых труб, включая впоследствии удалённые, не больше
  40 м;
- удаления ссылаются на ранее созданный и ещё активный PID; каждый PID удаляется
  не более одного раза.

Иных ограничений на порядок команд в этом классе нет. Значит, вход содержит не
более 6 нетерминальных команд. Обозначим сумму длин всех положительных команд
через `S`, а `H = 20 * ceil(S/20)`. Последовательное добавление каждой трубы в
конец траншеи — допустимое расписание с финальной длиной `H`; следовательно,
оптимум не больше `H`. В любом оптимальном расписании каждый когда-либо
занимавшийся интервал лежит внутри финальной траншеи, поэтому его целая
координата удовлетворяет `0 ≤ x ≤ H-L`. Перебор каждого целого `x` в этом
диапазоне полон; координаты за `H-L` не могут дать решение лучше `H`.

Для выбранных координат минимальная копка `T'` выше является допустимой и
слабее любой избыточной копки. Поэтому совместный перебор всех таких `x` и
минимальной копки охватывает оптимум всего заявленного класса.

Оракул объединяет одинаковые конфигурации активных PID и координат, сохраняя
меньшее `T`. Это безопасно: при одинаковой занятой геометрии состояние с меньшим
`T` может выполнить любую будущую последовательность координат, выкопав
недостающие секции тогда, когда они понадобятся; его финальное `T` не больше.
Все активные интервалы и PID остаются в ключе, так что удаление применяется
точно.

## Проверка до расширения поиска

`validate_oracle.py` сопоставляет DP с отдельной наивной рекурсией без слияния
состояний и проверяет ручные ожидаемые значения на мини-потоках. Включённый
ручной кандидат `+6, +7, -1, +8` проверяется отдельно против реально собранного
из frozen source solver. Массовый перебор входов пока не выполняется.

## Ограничения вывода

Точность оракула означает только глобальный минимум траншеи для каждого
отдельного потока в указанном классе. Она не доказывает что-либо о потоках с
более чем тремя размещениями, суммой длин выше 40 м, тестах Open15/holdout,
скрытых тестах или о качестве какой-либо причинной online-политики.
