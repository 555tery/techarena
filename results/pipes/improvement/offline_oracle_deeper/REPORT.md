# Offline oracle: диагностика сожаления на окнах Pipes

**Решение:** no-go для нового online-gate. Beam нашёл допустимые hindsight-свидетельства, но первые расхождения возникают при разных состояниях и разными геометрическими действиями. Общий причинный признак, который переносится с Open5/Open9 на независимые окна, не подтверждён. Кандидатная политика не создавалась.

## Проверка и границы

Зафиксированный baseline не менялся:

- `results/pipes/final/solution.cpp` — SHA-256 `c4b737b9a14588dd9895450acaff804b140691ef4d41bf1a0d68b6f13232a991`.
- `src/pipes.cpp` — SHA-256 `526ba58e955476105418593ebf0b3ef213dc4fe06fa601533e0aaf512a1dfec8`.
- Offline runner `results/pipes/improvement/offline_longbeam/longbeam` — SHA-256 `9e6c9f360381b6fc6f868d9fbaf687dc5d5a352def45579f95c5b2ae00ba904a`.

Все **30** новых запусков завершились с кодом 0. Runner сверяет каждый baseline output token на полном входе с сохранённой трассой. Для каждого окна baseline-control прошёл точный suffix replay и совпал с baseline final: **30/30**. Независимая проверка хэшей, контрольных результатов и ресурсов записана в `execution_validation.json`.

Это диагностика с доступом к будущим командам внутри выбранного окна. Beam ранжирует состояния, зная будущие длины запросов и PID, которые будут удалены в этом окне; после окна точный замороженный allocator воспроизводит весь суффикс без ветвления. Поэтому witness показывает физически достижимый hindsight-путь, а его экономия не является online-приростом score.

Поиск ограничен и не доказывает оптимум: на placement рассматривается максимум заданного action cap из отобранных fitting-gap/tail вариантов и краёв; все целые старты и все возможные последовательности не перебираются. Beam сортирует состояния по длине траншеи, эвристической оценке вместимости будущего спроса, максимальному gap и tail, затем отбрасывает состояния сверх width. Оценка вместимости складывает `floor(gap_length / pipe_length)` по длинам и может повторно учитывать одну ёмкость для разных будущих труб. Полный suffix score считается только для сохранившихся финалистов.

Эти состояния не выделяют переносимый gate: число fitting gaps среди положительных свидетельств равно 0, 8, 18 или 78; holdout с нулевым saving имеет 157. Положительные пути Open5 меняют адрес внутри нового tail или выбирают другую дыру; Open9 меняет край той же дыры; development uniform выбирает другую дыру из малого набора. Изменение действия само по себе ещё не означает выигрыш: holdout beam менял адрес при том же финале. Open5/Open9/Open15 в новых коротких окнах вообще не получили более короткого полного replay; в Open15 width64/cap12 даже первая divergence отсутствует.

Отдельно, в новой короткой выборке один development synthetic window дал 20–160 м экономии. Это подтверждает, что в конкретном потоке есть hindsight regret, но не показывает причинное online-правило и не оценивает перенос на другие synthetic inputs. Старые длинные окна Open5/Open9 также показывают разные механизмы. Учитывая размеры выборки и зависимость witness от будущих удалений, новый state gate по этому результату не оправдан.

## Вывод и воспроизведение

**No-go:** не менять online allocation policy по этим свидетельствам. Для обоснования следующего кандидата сначала нужна повторяемость одного причинно наблюдаемого состояния на нескольких новых независимых потоках; текущий набор её не показывает. Это no-go для текущей гипотезы, а не доказательство отсутствия лучшего online-алгоритма.

Воспроизведение сводки и реконструкции первой divergence:

```sh
python3 results/pipes/improvement/offline_oracle_deeper/analyze_witnesses.py
python3 results/pipes/improvement/offline_oracle_deeper/summarize_runs.py
```

Воспроизведение одного нового окна:

```sh
python3 results/pipes/improvement/offline_oracle_deeper/run_window.py \
  development_uniform_w64_a6 \
  data/pipes/synthetic/development/uniform.in \
  results/pipes/improvement/run48_qualification/runs/development_4/baseline/runs/uniform/judge_output.txt \
  2561 96 64 6
```

Solver `results/pipes/final/solution.cpp`, canonical `src/pipes.cpp` и платформа не изменялись. Подробный перечень хэшей лежит в `artifact_manifest.json`.
