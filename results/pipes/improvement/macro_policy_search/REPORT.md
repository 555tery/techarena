# TECH ARENA Pipes — macro-policy block screen и per-case envelope

## Краткий итог

Проверены четыре альтернативы размещения на 30 диагностических блоках длиной 256–4096 операций: всего **120 block-policy запусков** на cases 5, 9 и 15. Фактический сохранённый артефакт содержит `120/120` завершённых запусков со статусом `ok`. Они успели закончиться до позднего указания остановить прогоны; после этого указания новые тесты не запускались.

Ни одна политика не показала устойчивого выигрыша по наблюдаемым состояниям. `tail_only` дала отдельные выигрыши, но сильно ухудшала результат в дефиците подходящих дыр: до `+49 680 м` траншеи в case 5 и `+40 460 м` в case 15. Другие варианты также разнонаправленны. Следовательно, общий causal trigger из этого screen не извлечён; полный Open15 gate для macro-policy кандидата не запускался.

Отдельно собран hindsight envelope по всем ранее сохранённым полным Open15 результатам с совпадающими SHA-256 всех 15 входов. Среди 275 корректных полных запусков максимум по каждому кейсу, если выбирать разный запуск для каждого кейса, даёт сумму **29.829744313129 / 32.1** (`+0.040026384535` к текущему final). Это эмпирическая oracle-граница, составленная из разных кандидатов и потому не является результатом одного алгоритма. Самый высокий одиночный сохранённый full Open15 запуск — **29.791529008364 / 32.1**, всего на `+0.001811079770` выше current final.

## Macro-policy эксперименты

### Дизайн

Для каждого case 5, 9 и 15 выбраны состояния с высокой фрагментацией и низкой фрагментацией; для пяти длин блоков (`256, 512, 1024, 2048, 4096`) получено 30 block windows. Состояния отбирались по видимым признакам на baseline: размер запроса, число и объём свободных интервалов, крупнейшая дыра, длина хвоста и доля недавних расширений. Окна разных длин могут перекрываться. Каждый блок проверялся четырьмя политиками:

- `first_fit` — первый подходящий интервал по адресу;
- `tail_first` — сначала пригодный хвост, иначе baseline-поиск;
- `tail_only` — размещение в хвосте; при нехватке хвоста расширение, даже если есть внутренняя свободная дыра;
- `no_cohort` — обычный поиск без фильтра по когорте.

В отдельной диагностической копии политика действовала только внутри указанного диапазона операций, затем возобновлялась baseline-политика. Каждый запуск проходил весь тест через официальный interactor, так что для каждого варианта измерен итог после оставшегося suffix. Номер операции и case ID служили только для выбора диагностического окна и не являются предлагаемым онлайн-правилом.

### Скриншот результатов по policy × case

`Δ траншеи` ниже — `candidate − baseline`: отрицательное значение означает улучшение. Сумма Δ score относится к десяти выбранным диагностическим окнам данной пары policy/case; окна могут пересекаться, поэтому это только screen-статистика, а не оценка агрегатного KPI одного кандидата.

| 5 | tail_only | 0 / 0 / 10 | +160…+49 680 | −1.029577689 |
| 5 | no_cohort | 1 / 2 / 7 | −200…+1 040 | −0.029099835 |

Наблюдение с понятным механизмом, но отрицательным решением: `tail_only` теряет внутренние дыры именно в состояниях, где нет подходящей дыры под текущую трубу и расширение иначе можно было бы избежать. Единичные выигрыши case 9/15 не повторяются одинаково на похожих состояниях и блоках другой длины. `no_cohort` не изменил ни один из десяти screened запусков case 9 и case 15, то есть практического эффекта в этих состояниях не показал.

Сумма этих трёх screen deltas `+0.013055930101` — **не Open15 score**: для каждой строки выбрана своя политика и точка блока после просмотра результатов, 12 кейсов не тестировались. Macro варианты не объединены в один solver и не прошли holdout или 10 synthetic gates.

## Проверка и ресурсы

- Control прогон диагностического runner без макрополитики побайтно совпал с final judge traces cases 5, 9, 15; итоговые траншеи совпали: 62 760 м, 61 960 м, 438 920 м.
- Все 120 macro-policy запусков: protocol `ok`; максимальный CPU `2.908853 с`, пиковая память `5.5625 MiB` при лимитах 5 с и 256 MiB.
- Из 120 запусков в четырёх блоках конец блока совпал с концом теста; у остальных полный suffix содержал от 1 до 185 697 команд. Все прогоны всё равно проходили interactor до завершения теста.
- `results/pipes/final/solution.cpp` сохранил SHA-256 `c4b737b9a14588dd9895450acaff804b140691ef4d41bf1a0d68b6f13232a991`; `src/pipes.cpp` — `526ba58e955476105418593ebf0b3ef213dc4fe06fa601533e0aaf512a1dfec8`. Финал и платформа не изменялись.
- У macro runner SHA-256 source `208d556ab3f385011ce411ccc3b34f22b57220c7f685d42f2780bcdacb144063`, binary `29ae58e27ea131b59be93161f52f62e72845c50f8efa892193e8197cd6163800`.
- Новый holdout или synthetic не запускался: по результатам screen не сформирован causal online кандидат, требующий квалификационного gate.
