# Независимый поиск эвристики размещения

## Вопрос и правило эксперимента

Проверяется один новый класс: **online demand-aware best-fit**. Для каждого запроса длины `L` solver учитывает только прошлые положительные команды в скользящем окне. Для возможного свободного интервала длины `G` residual `r = G - L` оценивается как

`cost(r) = r * n_recent - bonus * count_recent(pipe_length <= r)`.

Чем меньше cost, тем предпочтительнее интервал. Этот скоринг пытается оставить свободные промежутки, которые по недавно наблюдавшимся длинам вероятнее пригодятся для повторного размещения. Чтобы сохранить логарифмический поиск, кандидаты — обычный best-fit плюс интервалы, найденные поиском по mode, q25, q50, q75 и q90 недавних длин. При равном cost сохраняется tie-break меньший размер, затем меньший адрес. Хвост траншеи остаётся обычным свободным интервалом. Если подходящего места нет, расширение хвоста идентично baseline.

До запусков зафиксирована матрица из шести конфигураций: окна `32`, `128`, `512` положительных запросов и бонусы `10` или `40` метров. Это небольшой исследовательский sweep по открытым тестам; он не является статистической оценкой скрытого распределения и не использует frozen holdout-v2. Улучшение open score само по себе не будет трактоваться как доказательство лучшей общей стратегии.

## Сборка и оценка

Baseline — байт-в-байт копия замороженного policy4. Все кандидаты собираются из `source/demand_aware.cpp` только с разными `DEMAND_WINDOW` и `DEMAND_BONUS_METERS`. Каждый бинарник запускается официальным `tools/pipes_harness.py` по всем `data/pipes/open/*.in`; сравнение включает полный weighted score, per-case KPI и trench length, CPU и RSS. Официальные лимиты harness: 5 s CPU и 256 MiB RSS на solver. Команды, хеши, исходные JSON/CSV отчеты и объединенная per-case таблица сохраняются только в этой директории.

Ни `src/pipes.cpp`, ни официальный interactor, ни другие каталоги для этого эксперимента не меняются.

## Сравнение с `recent_unfit_s50`

После первоначального sweep demand-aware W32/B10 отдельно сопоставлен с открытым лидером strategy-агента `recent_unfit_s50` тем же официальным harness на тех же 15 открытых входах. Score: `28.4235657495/32.1` против `28.9394589403/32.1`, то есть W32/B10 уступает на `0.5158931908`. Сверка SHA-256 подтвердила одинаковые файлы тестов во всех парных отчетах; оба solver прошли 15/15 тестов. Покейсовые KPI, длины траншеи, взвешенные разницы, хеши, ресурсы и точные пути находятся в `REPORT_recent_unfit_s50.md`, `per_case_vs_recent_unfit_s50.csv` и `comparison_recent_unfit_s50.json`.

`recent_unfit_s50` использует окно последних 128 размещений и штраф 50 для recent demand heuristic (`PIPES_STRATEGY=2`). Исходник и бинарник принадлежат каталогу `results/pipes/improvement/strategies/`; сюда они не копировались и не изменялись. Скрытые/holdout тесты не использовались ни для этого сравнения, ни для отбора конфигурации.

## Отдельная synthetic robustness-suite

По просьбе координатора существующий бинарник W32/B10 также прогнан на 10 ранее зафиксированных синтетических потоках из `results/pipes/improvement/strategies/robustness_inputs/`. SHA-256 входов сверены с `robustness_manifest.json`; для policy4 и s50 используются соответствующие уже сохранённые official-harness отчёты. Параметры и бинарник W32/B10 не менялись. Результаты, точные дельты по каждому потоку, проверенные hashes и короткая рекомендация: `ROBUSTNESS_REPORT.md`, `per_case_robustness_frozen.csv`, `robustness_frozen_comparison.json`.
