# Диагностика сохранённых результатов SEARCH v2

`diagnose.py` читает завершённые отчёты SEARCH-v2 и создаёт отдельный снимок диагностики.
Текущий evaluator, SQLite, fitness, prompt и feedback модели не меняются.
Solver, interactor, компилятор и модель не запускаются. Исходные `.in`, Validation
и Open15 не открываются; используются только манифест и сохранённые артефакты SEARCH-v2.

## Показатели

- **Худшие 16 потоков поколения:** минимальные B/T, при равенстве — порядок case id.
  В таблице есть B, T, лишние метры относительно B, относительный перерасход и ΔT к baseline.
- **Фиксированные худшие 16 baseline:** те же case id во всех поколениях, чтобы
  изменение состава худшей группы не скрывало изменения на исходно слабых случаях.
- **Все 16 семейств от худшего к лучшему:** средний B/T, средний перерасход,
  худший отдельный B/T и изменение среднего к baseline.
- **Средний перерасход:** среднее `T/B - 1` внутри семейства, затем по семействам.
  В JSON хранится доля, в отчёте — проценты. Это не `1/mean(B/T)-1`.
- **Регрессии к baseline:** потоки с увеличением T и счётчики лучше/хуже/равно.

B — округлённая объёмная нижняя граница, не обязательно достижимый оптимум.
Все сравнения относятся к поколению 0 выбранного запуска. Для текущего запуска
оно является точной копией поколения 2 прошлого SEARCH-v1.
Старый score SEARCH-v1 в расчёте не используется.

## Повторное чтение результатов

Нужно указать каталог SEARCH-v2 запуска и новый каталог вывода внутри `analysis/`:

```sh
/Users/555tery/techarena/shinka-pipes/.venv/bin/python \
  /Users/555tery/techarena/shinka-pipes/analysis/diagnostics/diagnose.py \
  --run-dir /Users/555tery/techarena/shinka-pipes/search-v2/runs/20261018T011836+0700-084000 \
  --out-dir /Users/555tery/techarena/shinka-pipes/analysis/diagnostics-new-snapshot
```

По умолчанию рассматриваются существующие поколения; `--generation 0 --generation 1`
фиксирует нужный список. Baseline 0 всегда добавляется для сравнения.
Поколения без маркера завершения обозначаются `incomplete`, отклонённые — `rejected`;
им не присваиваются вымышленные значения диагностики. Неполные/повреждённые
положительные отчёты отклоняются при проверке привязки и полноты.
Готовый каталог вывода не перезаписывается, запись внутрь SEARCH-v2 запрещена.

Сохраняются `REPORT.md` и `diagnostics.json` с формулами, происхождением и SHA256
прочитанных артефактов. Результат является дополнительной диагностикой;
автоматическое включение в отбор или текстовый feedback текущего запуска отсутствует.

## Проверка самого расчёта

`test_diagnose.py` проверяет арифметику, баланс семейств, смену состава худших 16,
проверку происхождения, полноту, ресурсные границы и ограничения путей.
Используются числовые таблицы и временные JSON-файлы; ни одного входного `.in`
для тестов не создаётся, исполнение subprocess запрещено в проверке CLI.
