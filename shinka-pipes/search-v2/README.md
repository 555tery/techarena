# SEARCH v2 для следующего запуска Shinka

Подготовлены 128 поисковых потоков, по 8 на каждое из прежних 16 семейств,
и пакет из шести работ и трёх реализаций аллокаторов с шестью гипотезами изменения алгоритма.
По запросу пользователя 18 октября 2026 SEARCH-v2 перезапускается от поколения 2
прошлого SEARCH-v1 с бюджетом **30 поколений, включая новый baseline поколения 0**.
Предыдущий старт от исходного baseline остановлен, артефакты сохранены.
Validation и Open15 не читались.

## Входы и разнообразие

Набор: `task/data/search/`; манифест: [manifest.json](task/data/search/manifest.json).
Всего **10870000 команд**, **49542596 байт входов**. Число команд на поток —
от 8000 до 200000; у `large_live_set` — 80000–200000.

Все 16 семейств сохранены: uniform_churn, short_heavy, long_heavy, bimodal,
section_boundaries, fifo, lifo, size_lifetimes, burst_drain, distribution_switch,
drifting_sizes, striped_recycling, geometric_cohorts, additive_cohorts,
large_live_set, size_biased_deletion. Четыре механизма старого validation не добавлены.

Различаются seed, длина потока и применимые к семейству параметры:

| Механизм | Разнообразие |
|---|---|
| Churn, FIFO, LIFO, серии, size-biased | Целевой live set 24–16384, вероятность удаления 0.10–0.82, начальная загрузка |
| Крупный live set | Цели 2048–45000, вероятность удаления 0.02–0.28 |
| Распределения размеров | Разный перекос, смесь коротких/длинных, наборы около 20 и 40 |
| Смена режима | Длительность фазы 127–8191 команд, сдвиг фазы и профиль размеров |
| Геометрические и аддитивные серии | Длина серии 17–4093, несколько последовательностей, шаг и направление |
| Зависимость срока от размера | Положительная, отрицательная и меняющая знак; разные масштабы экспоненциального времени |
| Пакеты и полосы | Размер пакета, доля удаления, период полос |
| Дрейф размеров | Скорость изменения центра и ширина окрестности |

Общие поля спецификации, не используемые данным механизмом, не влияют на поток.
`target_live` — управляющий параметр, а не обещание точного числа живых труб.
Фактические диапазоны и все параметры записаны в [preparation.json](preparation.json).
Например, у stripe-сценариев накапливаются сохраняемые части когорт, поэтому пик
может быть значительно выше target. Это допустимая нагрузка в пределах 200000 команд.

Новые seed и содержимое не совпадают с SEARCH-v1; проверено по его манифесту.
Содержимое и метаданные validation/Open15 для проверки пересечения не открывались.
Новый набор является поисковым, а не независимым holdout: предыдущие SEARCH-результаты
уже известны. Входы не отбирались по оценке какого-либо кандидата.

## Что проверено

Каждый поток прошёл аудит допустимых размеров, существования удаляемого PID,
количества команд, положительного финального объёма и peak live volume.
Записанные файлы независимо разобраны существующим parser из harness.
Проверены SHA256, уникальность 128 файлов и покрытие 8 × 16.

[test_preparation.py](test_preparation.py) проверяет воспроизводимость всех вариантов,
семантику FIFO/LIFO, маршруты evaluator, отсутствие запуска при default/check,
явный бюджет, gate полного baseline и формулу fitness на искусственных отчётах.
Новый старт сначала выполняет сквозной baseline на всех 128 потоках SEARCH-v2.

## Готовая отдельная задача

В `task/initial.cpp` находится точная копия `gen_2/main.cpp` из
`shinka-pipes/runs/20261017T232542+0700-833000/`, явно выбранная пользователем.
SHA256: `e3ee5b3551a2b46fe166ca29414c5c1703aa6f9397b49aa776c9c3e8f4f4de7e`.
Это поколение 0 нового прогона; его старый score не переносится на SEARCH-v2.
Interactor source, harness, 128 входов, веса и ресурсные лимиты сохранены.

`evaluator.py` использует единственный фиксированный путь `task/data/search`.
Метрика сохранена: среднее B/T внутри семьи, затем среднее по 16 семьям;
B = 20 ceil(peak live volume / 20). Все 128 случаев должны быть корректны,
CPU < 5 s и RSS < 256 MiB. Пропуск, ошибка или превышение лимита отклоняют кандидата.

`task/shinka.yaml` уже включает [литературный prompt](research/prompt.txt).
Разбор [malloc, jemalloc и mimalloc](research/ALLOCATORS.md) сопоставлен с baseline
и gen2. Новые [H4–H6](research/ALLOCATOR_IDEAS.md): сохранение расширяемого хвоста,
возраст равноценных свободных дыр и повторное заполнение текущих регионов.
Приоритет рассмотрения — H4/H5/H2, затем H1/H3/H6; это не дополнительный бюджет.
Модель `headless/codex@gpt-6-astra?effort=xhigh`, режим **Fast**, billing subscription,
один worker на этап, без embeddings/meta/W&B. В этой отдельной конфигурации
разрешены три попытки применения патча с feedback: исходная и до двух исправлений.
Все попытки используют одного родителя и один номер поколения; до успешного
применения evaluator не вызывается. Каждая попытка сохраняет ответ и ошибку.
При исчерпании попыток v2 останавливается со статусом `needs_patch_repair`,
сохраняя `patch-repair-exhausted.json`; следующего поколения и автоматического
перезапуска нет, ошибочный Program в счётчик не добавляется. Вызовы для исправления
расходуют подписку, но не создают дополнительные поколения.
Это поведение закреплено в [patch_repair.py](patch_repair.py) и проверено
[на искусственных ответах](test_patch_repair.py), без моделей и исполнения C++.
У текущего SEARCH-v1 настройки прежние.
Модель допускается только после успешного gen 0 на всех 128 потоках v2.
Fast закреплён в `headless_bridge.py` через `--fast`: установленный Headless
передаёт Codex `service_tier="fast"`. Глобальные настройки Codex не меняются.
Доступность модели проверяется при запуске; baseline gate предшествует всем запросам модели.
Gate связывает отчёт с исходником, evaluator, snapshot и манифестом этого прогона.
Код и протокол закреплены в [snapshot.json](snapshot.json) и [protocol.json](protocol.json).
Проверка защищённого кода допускает отсутствие одного конечного перевода строки:
его удаляет штатный diff-applier Shinka. Содержимое защищённого кода проверяется строго.
Маршруты evaluator и инструкции задают логическое разделение наборов;
отдельной OS-изоляции файловой системы процесса кандидата здесь нет.

Безопасная проверка подготовки, без запуска кандидатов и модели:

```sh
/Users/555tery/techarena/shinka-pipes/search-v2/run.sh --check
```

Разрешённый запуск: `--run --generations 30`, поколения 0–29.
Актуальный каталог и панель указаны в [active-run.json](active-run.json).
Score 0.914984 или 0.932003 из v1 не является baseline-оценкой v2
и напрямую с новыми v2 оценками не сравнивается.

## Идеи и дальнейший порядок

[Разбор работ и гипотезы](research/IDEAS.md):

1. Возрастно-условный риск удаления с учётом живых цензурированных наблюдений.
2. Точный глобальный адресный First-Fit с эффективным индексом.
3. Исправление ошибочных lifetime-меток уже существующей арены.

Сначала будущая оценка baseline на полном v2, затем ограниченный поиск по одному
механизму за предложение и абляции. Успех на SEARCH не устанавливает перенос
на платформу. Validation и Open15 в этой задаче не оцениваются.
