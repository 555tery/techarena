# Учёт регрессий и сохранение специалистов

Статус `prepared_not_run`, протокол `family-specialists-v1` для SEARCH-v3.1.
Основной `combined_score`, итоговый лидер и обычный архив Shinka используют
прежнее среднее F/T. Код `fitness.py`, 152 main-входа и 64 stress-входа не менялись.
Настройки отбора заранее записаны в `selection-policy.json`; это инженерные
начальные значения, их эффективность ещё не проверялась экспериментом.

## Регрессии

Опорная программа — выбранный для будущего запуска baseline поколения 0.
Для каждого main-потока считается `loss_i = max(0, baseline_F/T_i − candidate_F/T_i)`.
Основная дополнительная характеристика — среднее 16 наибольших loss из 152,
включая нули. Также сохраняются максимальная потеря, число ухудшенных потоков,
изменения по всем семействам и восемь крупнейших потерь.
Улучшения на других потоках не компенсируют этот показатель. Низкий исходный F/B
сам по себе не считается регрессией. Показатель зависит от выбранного baseline;
он не доказывает устойчивость на неизвестных распределениях.

## Выбор родителей

Повторяется цикл по номеру поколения, начиная с gen1:

1. Штатный выбор Shinka по основному score.
2. Штатный выбор по score.
3. Выбор с учётом регрессий.
4. Штатный выбор по score.
5. Выбор специалиста.

В третьем слоте рассматриваются корректные программы в пределах **0,005 F/T**
(0,5 процентного пункта) от лидера выбранного острова. Среди них выбирается
меньшая средняя потеря на худших 16 потоках, затем меньшая максимальная потеря,
затем большее среднее F/T. Это не штраф к fitness и не запрет всех регрессий.

В пятом слоте выбирается один из различных по исходнику победителей семейств,
кроме лидера острова по среднему F/T. При неизменном составе они чередуются.
Если отдельных специалистов нет, сохраняется штатный выбор. Победитель семейства
определяется по среднему F/T его четырёх случаев; при равенстве предпочтительнее
большее общее среднее, затем меньшие регрессии. Сильная идея на одном из четырёх
вариантов всё ещё может быть скрыта средним семейства — это граница текущей схемы.

Штатный sampler продолжает выбирать остров. Родители и inspirations остаются
внутри него. При инициализации островов штатный родитель сохраняется; fix mode
не подменяется. Некорректные, неполные, чужие и ещё не завершённые поколения
не допускаются в обычный отбор. Копии исходника не дают дополнительных шансов.
Весь repair остаётся на выбранном родителе и в прежнем лимите трёх попыток.

## Сохранение и возобновление

Отдельный реестр содержит победителя каждого семейства глобально и на каждом
острове. Он строится из **всех** корректных записей `programs.sqlite`, включая
исключённые из обычного архива на 20 мест. Установленная Shinka удаляет при
вытеснении только членство в архиве, исходник и результаты остаются в базе.
Реестр не ограничивает обычный scalar-архив и не меняет его рейтинг.

- `run/selection-state.json`: производный реестр, профили и baseline; обновляется
  после setup, перед выбором родителя и при штатном завершении.
- `run/gen_N/selection-context.json`: фактический режим, первоначальный и выбранный
  родитель, его регрессии, выигранные семейства и оставленные inspirations.
- `metrics.json`: отдельные `selection_diagnostics`, включая сравнение с baseline;
  в `combined_score` по-прежнему только среднее F/T.
- `research-context.json` и prompt: причина выбора родителя и его регрессии.

После resume реестр восстанавливается из SQLite; его потеря не теряет специалистов.
Цикл привязан к номеру поколения. Политика детерминирована при том же снимке базы
и исходном выборе острова/родителя; случайность штатного sampler не отменяется.
Новая оценка кандидатов для этого не нужна. Порядок/состав специалистов может
меняться по мере поступления новых результатов.

## Проверка и ограничения

Проверки используют искусственные результаты, настоящую временную SQLite-базу
Shinka и её `get_async`. Компилятор, solver, interactor и модель не запускаются.
Проверяются потери и нули, граница 0,005, специалист вне scalar-архива, сохранение
основного лидера, island/fix/bootstrap, неполные/чужие данные и resume.
Реальный выигрыш такого отбора пока не установлен.

Входные корпуса, stress-маршрут, validation, Open15, модель GPT-6.1 Sol xhigh без Fast,
два потока evaluator и бюджет будущего запуска сохраняются. Seed и разрешение запуска
по-прежнему не назначены. Запуск требует отдельной команды пользователя.

Отчёт текущей проверки: [selection-verification.json](selection-verification.json).

Ночной режим допускает 2 параллельных предложения и до 10 островов. Снимок выбора
привязан к номеру предложения; он может иметь пропуски после исчерпанного repair.
Число активных островов восстанавливается из SQLite, а специалисты по-прежнему
выбираются внутри выбранного острова. Общий F/T-лидер не меняется.
