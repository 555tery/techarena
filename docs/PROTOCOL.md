# Pipes: протокол и локальная проверка

Правила сверены с `data/pipes/statement.pdf` и локальной копией официального
исходника интерактора в `vendor/pipes_official/`.

## Интерактивный протокол

Интерактор передаёт по одному целому числу. Положительное `L` означает трубу
длиной 1–40 м. В ответ программа печатает `N D` на одной строке: вырыть `N`
секций по 20 м и уложить трубу с координаты `D`. Отрицательное число `-K`
означает удаление трубы с PID `K`; в ответ нужно напечатать исходную координату
этой трубы. PID — порядковый номер укладки, начиная с 1; после удаления он не
переиспользуется. В конце интерактор передаёт `0`; на него отвечать нельзя,
после него программа должна завершиться. Каждая команда ответа заканчивается
переводом строки и сбросом буфера до чтения следующей входной команды.

Официальный интерактор читает числа как поток whitespace-разделённых токенов.
Локальный harness дополнительно требует ровно одну строку ответа на команду:
два целых числа для укладки и одно для удаления. Он также проверяет перевод
строки, отсутствие вывода после финального `0` и быстрое завершение программы.

Интерактор проверяет пересечения труб, достаточную длину траншеи, координату
удаляемой трубы, лимит траншеи 100 000 000 м и положительную финальную длину
траншеи. Он считает `KPI = суммарная длина оставшихся труб / длина траншеи`, а
затем записывает `KPI × вес теста` в `score.txt` текущей папки конкретного теста.

## Лимиты и баллы

- В одном сценарии не более 200 000 команд.
- Длины труб — целые числа от 1 до 40 м.
- Траншея удлиняется секциями по 20 м; её максимум — 100 000 000 м.
- Лимит участника — менее 5 секунд CPU и менее 256 МБ памяти.
- Итоговый балл — сумма взвешенных KPI по 30 тестам. Сумма весов 15 открытых
  тестов равна 32,1; веса закрытых тестов в сумме дают 84. Максимум — 116,1.

Harness разделяет CPU программы и wall time проверки. CPU процесса solver —
сумма user+system, пик памяти берётся из `wait4` только для дочернего процесса
solver. На macOS поле `ru_maxrss` задано в байтах, на Linux — в KiB. Wall time
включает Python harness, solver и interactor; на тесте с 200 000 командами он
заметно выше CPU solver из-за обмена и сброса буфера после каждой команды.
CPU и память интерактора также записываются отдельно и не входят в лимит solver.

## Нижняя граница для входного сценария

Для каждого потока команд harness считает суммарную длину труб, которые ещё не
удалены. Пусть `P` — максимум этой суммы в любой момент, а `F` — длина труб,
оставшихся в конце. Траншея не сокращается, а её длина кратна 20 м, поэтому
любому решению нужна траншея не короче `ceil(P / 20) × 20` м. Отношение
`F / (ceil(P / 20) × 20)` — верхняя граница возможного KPI только по объёму.
Фрагментация и запрет перемещать трубы могут сделать достижимый KPI ниже.
Если `F = 0`, граница записывается как 0.

В отчётах стратегия сравнивается с этой границей через безразмерную метрику
`lower_bound_trench / actual_trench`. Она равна `actual KPI / upper-bound KPI`:
1 означает достижение объёмной границы, меньшее значение показывает потерю из-за
расположения труб. Для набора приводятся среднее и минимум по тестам. При
сравнении двух стратегий дополнительно записывается по каждому тесту
`candidate_trench / baseline_trench - 1`; положительное значение означает, что
кандидату потребовалась более длинная траншея. KPI-отношение считается отдельно
и не смешивается с этим regret.

## Воспроизведение

Скрипт `runner.py` из скачанного архива не используется: если `psutil` отсутствует,
он пытается установить этот пакет. Локальные инструменты используют только
стандартную библиотеку Python. Интерактор компилируется из скопированного
официального C++-исходника; скачанные готовые исполняемые файлы не запускаются.

```sh
make interactor
python3 tools/pipes_harness.py \
  --solver ./results/pipes/binaries/pipes-final \
  --name final-source \
  --tests data/pipes/open \
  --out results/pipes/manual-open-run
```

Воспроизвести историческое сравнение пяти вариантов `PIPE_POLICY` на сохранённом
снимке источника:

```sh
python3 tools/compare_pipes.py --source results/pipes/policy-comparison/source.cpp \
  --tests data/pipes/open \
  --out results/pipes/policy-comparison
```

Для сравнения уже собранных бинарных файлов на одном и том же наборе тестов
используйте `tools/compare_pipes_binaries.py`. Отчёты сохраняют hashes бинарных
файлов, результаты официального интерактора и агрегаты solver CPU/RSS отдельно
от wall time orchestration. JSON включает сравнения по каждому тесту, а CSV
`per-case-comparison.csv` содержит эти данные в табличном виде.

Открытые тесты не заменяют закрытый набор. В репозитории сохранён отдельный
holdout-v2 из 12 независимых фиксированных сценариев для итоговой проверки;
его inputs и hashes находятся в
`data/pipes/synthetic/final-holdout-v2/manifest.json`. Это локальная robustness-
проверка, не официальный закрытый набор. Не использовать holdout для настройки
стратегий.

Пример воспроизводимого синтетического теста:

```sh
python3 tools/generate_pipes_synthetic.py \
  --seed 71923041 --operations 20000 --length-profile uniform \
  --churn 0.42 --batch 500 --deletion-policy random \
  --out data/pipes/synthetic/example.in
python3 tools/pipes_harness.py \
  --solver ./results/pipes/binaries/pipes-policy-0 \
  --name bestfit-preserve-tail \
  --tests data/pipes/synthetic/example.in \
  --out results/pipes/synthetic-example
```

Генератор фиксирует последовательность PRNG через seed, использует длины труб
1–40 м, удаляет только активные PID (random/oldest/newest/shortest/longest) и
ограничивает сценарий 200 000 командами.
Последняя команда генератора всегда укладывает трубу, чтобы тест сравнивал
стратегии при положительной финальной загрузке. Вес синтетического теста служит только для локального отчёта; его нельзя
прибавлять к официальной сумме по открытым тестам 32,1.
